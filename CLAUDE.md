# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`xcli` is a CLI tool for the [xcore](https://github.com/traoreera/xcore) Python framework. It covers the full lifecycle of an xcore application: project initialization (config generation), plugin management (install/update/remove), and deployment. The CLI is invoked as `xcli`.

**Stack:** Python 3.12+, [Typer](https://typer.tiangolo.com/) (CLI), [Rich](https://rich.readthedocs.io/) (terminal UI), PyYAML, `xcore` (installed from git).

## Setup & running

```bash
uv sync                  # Install dependencies (uses uv, not poetry)
uv run xcli --help       # Run the CLI
uv run python test.py    # Run test entry point
```

The `.venv` is managed by `uv`. The `xcore` dependency is pulled from `https://github.com/traoreera/xcore.git`.

## Project structure

```
xcli/
  init/
    cli.py       # Typer sub-app with the `init` command
    manager.py   # Interactive wizard logic (Rich prompts → integration.yaml)
```

The main entry point registered in `pyproject.toml` is `xcli = "xcli.init.cli:app"`. Currently only one command exists: `xcli init`.

### How commands are wired

Each feature area gets its own sub-package under `xcli/` with a `cli.py` exposing a `Typer()` instance. The root app in `xcli/init/cli.py` should eventually register these as sub-apps via `app.add_typer(...)`. The interactive logic lives in a `manager.py` beside each `cli.py`.

## `integration.yaml` schema

The config file generated by `xcli init` and consumed by `xcore`:

```yaml
app:
  name, env, debug, secret_key, plugin_prefix, plugin_tags, server_key, server_key_iterations
plugins:
  directory, entry_point, interval, secret_key, strict_trusted
services:
  databases: [{name: {type, url, pool_size, max_overflow, echo}}]
  cache:     {backend, ttl, max_size, url}
  scheduler: {enabled, backend, timezone}
```

Supported DB types: `sqlite`, `sqlasync`, `mysql`, `mongodb`, `postgresql`, `redis`.

## Planned CLI surface

The CLI is intended to cover:
- `xcli init` — interactive config wizard → `integration.yaml` *(implemented)*
- `xcli plugin add/remove/list/update` — plugin lifecycle management *(to build)*
- `xcli deploy` — deployment to server *(to build)*
- `xcli service start/stop/restart/status` — server management *(to build)*

## Notes

- The `makefile` at the root belongs to the **xcore** server project (references `poetry`, `uvicorn main:app`, etc.) and is used as a reference for what the CLI should automate — it is not the build system for `xcli` itself.
- `xcore` imports (e.g. `xcore.configurations.sections.AppConfig`) require the venv to be active; `uv run` handles this automatically.
